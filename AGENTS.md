# punchlist - notes for agents

See README.md for what this is. TypeScript throughout. Layout: `src/cli.ts` (proxy + CLI, uses `axi-sdk-js`), `src/punchlist-axi.ts` (entry: `--version` fast path), `src/client/` (picker injected into pages: Svelte 5 mounted into a shadow root by `index.ts`; `App.svelte` holds the state, the other components only render; `page.ts` = page gestures + pause, `context.ts` = selectors/source hints/markdown, `storage.ts`, `api.ts`; `editor.ts` = CodeMirror, its own lazily imported bundle), `src/protocol.ts` (the note/request types both sides share), `test/` (`pnpm test`: proxy e2e against a fake Rails-like server, client flows in jsdom with stubbed layout; run with `tsx`). `pnpm build` (`build.ts`, esbuild) bundles them into `scripts/punchlist-axi.mjs`, `scripts/punchlist-cli.mjs`, `scripts/client.js` and `scripts/editor.js`; these are committed, shipped, and must never be edited by hand - `pnpm test` rebuilds first. `pnpm check` = `tsc` (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, one tsconfig per runtime: node `src/`, browser `src/client/` (checked by `svelte-check`), `test/`) + ESLint (typescript-eslint `strictTypeChecked` + `stylisticTypeChecked`, a few rules tuned in `eslint.config.js`); CI runs both. `skills/punchlist/SKILL.md` is the published skill (`npx skills add narze/punchlist-axi --skill punchlist`; it calls `npx -y punchlist-axi`), `.claude/skills/punchlist/SKILL.md` is the dev copy that runs the local build. Both are thin stubs; the CLI (`--help`, next-step lines) is the source of truth for agent guidance.

## Hard requirements

1. **No changes to the target app.** Must work in front of any server: Rails (ERB, Turbo, ActionCable), SvelteKit/Vite, React, static.
2. **Works on a phone over Tailscale.** This is why it is a proxy and not a browser extension.
3. **AI-agnostic.** Any agent that can run shell commands must be able to drive it. No MCP requirement, no vendor CLI baked in.
4. **Only `node` (>= 18) or `bun` needed at runtime.** Source may use libraries (decision 2026-10-12: `axi-sdk-js`), but releases ship bundled files (`scripts/punchlist-axi.mjs`, `scripts/punchlist-cli.mjs`, `scripts/client.js`, `scripts/editor.js`), no install.

## Decisions (do not reopen without a reason)

| Considered | Outcome | Why |
|---|---|---|
| Chrome extension | Rejected as primary | No mobile, per-device install. Could be another client of the same daemon later. |
| Dev-only `<script>` tag in the app | Rejected | Breaks requirement 1. |
| iframe "browser in browser" | Rejected | Cross-origin iframe DOM is inaccessible; a same-origin proxy solves it. |
| `http-proxy-middleware` | Hand-rolled Node `http` proxy | Small, no runtime deps. |
| Agent handoff via MCP | `wait`/`done` CLI instead | Works with every agent. |
| Upstream sees `X-Forwarded-*` | Stripped on purpose | Rails would use the tailnet host and fail Host Authorization / CSRF origin checks. Upstream must see a plain `localhost` request. |
| Skill holds the workflow text | Thin stub, CLI holds guidance | Copied from lavish-axi: installed skills go stale, the CLI does not. |
| `start` in the foreground + `nohup` | `start` spawns a detached `serve` | The agent never manages processes. |
| Phone access via `tailscale serve` | `start` also binds the Tailscale IPs, prints `http://<name>.ts.net:<port>` (2026-10-12) | No extra step for the user. Tailnet-only (not `0.0.0.0`, not funnel), token still required; skipped with `--no-tailscale`, `--no-auth` or an explicit `--host`. |
| AXI (https://axi.md) | Adopt, with `axi-sdk-js` + bundled release | See docs/axi-plan.md. |
| Plain JS | TypeScript + esbuild, strict tsc + typescript-eslint (2026-10-12) | The client and proxy share one wire format (`src/protocol.ts`); esbuild already bundled the release. TypeScript stays on 6.0 until typescript-eslint supports 7. |
| In-page editor: Monaco | CodeMirror 6 (2026-10-12), a ✎ Edit button in the note panel, no mode or server flag | Monaco is poor on phones and needs web workers. CodeMirror mounts in the shadow root (`root` option). ~200 KB gzip, so it is a separate ES module (`scripts/editor.js`) the picker `import()`s on first use. Writes are limited to source files (no dotfiles, node_modules, git-ignored, binary) and refused on a stale etag (409); the access token already lets anyone drive the agent, so no extra opt-in. |
| Hand-written DOM in the client | Svelte 5 (2026-10-12) | Declarative UI is easier to change; the maintainer knows Svelte. Built with `esbuild-svelte`, `css: 'injected'` (lands in the shadow root), `discloseVersion: false` (no `window.__svelte` on the app's page), minified (drops Svelte's dev branches). Costs ~33 KB gzip vs ~10 KB, so the proxy gzips `client.js`. Preact/Lit were the lighter options. |

Prior art (none meets all 4 requirements): Agentation (React-only, needs a component, desktop-only, PolyForm Shield license - ideas only, never copy code), React Grab (React-only), stagewise (now a full browser/IDE), VS Code "Add Element to Chat", Cursor Design Mode, Claude Code Desktop Preview, Pinpoint (VS Code). lavish-axi is the model for the agent loop (long-poll, presence, receipts).

## Verified so far

Desktop Chromium against GeekCraft (Rails + Turbo, on another tailnet host) and 4do (SvelteKit/Vite): auth, injection, URL rewriting, click/drag/area/text notes, Turbo navigation, CSRF form POST, Send -> `wait` -> `done` -> toast, 390px layout. ↗ Open (open in editor) checked in desktop Chromium and at 390px against the test fixture with a fake `LAUNCH_EDITOR`, not with a real editor. ↗ Open from another machine (editor URL over Remote-SSH, `--editor-url`) and ⧉ Copy (2026-10-12): desktop Chrome against 4do through the tailnet IP, the vscode:// URL recorded rather than followed; the user then confirmed it opens in their editor. 🔎 Locate (agent finds the file when hints name none, answered with `done --open`) is the fallback for every framework - decision 2026-10-12: the agent locates, not a proxy-side grep. Svelte client (2026-10-12): desktop Chrome against the test fixture, driven by JS events with the tab hidden (no screenshots, no rAF): mount, styles in the shadow root, hover/pick/drag, app clicks and keys swallowed, add note, tray, Escape, Send -> `wait` -> `done` -> toast; also against 4do (SvelteKit, Svelte 5 dev) the same way: app and picker clicks each fire once with two Svelte runtimes on the page, the app's own `window.__svelte` is untouched, pick mode blocks app clicks and keys, `__svelte_meta` hints reach `wait`, no console errors. In-page editor (2026-10-12): desktop Chrome, tab hidden, JS events, against a scratch Rails-like app and 4do: ✎ Edit mounts CodeMirror in the shadow root (styles adopted there, no page globals), keys don't reach the app, ⌘S saves to disk, conflict -> Load from disk, two-step Close, annotate mode restored, header drag moves and the corner resizes (CodeMirror follows), double-click resets, monospace font, no console errors; locate-for-editor only in the e2e test. URL sheet (2026-10-14): desktop Chrome at 390x844 against the test fixture: pill fits, icons, pre-filled and selected, typed path, pasted full URL, `javascript:` refused with the error line, recents, Back, Alt+Shift+L, draft `confirm()` (No stays, Yes leaves), bfcache restore closes the sheet; Forward, Reload and Escape only in jsdom. Touch in annotate mode (2026-10-14, decision: drag scrolls, tap picks, long press (350 ms) then drag selects): headless Chrome with Pixel 7 emulation and real CDP touch events against a tall static page: swipe scrolls natively, tap picks, long-press drag draws the marquee with no scroll, a tap on a link does not navigate, no console warnings. Not verified: real phone (iOS Safari; touch scrolling and long press also not on a real Android), the editor at 390px and on touch, Vite HMR socket through the proxy, ActionCable, ⏸ pause. Always say what was checked in a real browser vs only in jsdom.
